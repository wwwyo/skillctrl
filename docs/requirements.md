# Go rewrite and public release

## User request

Publish skillctrl as broadly usable open source, keeping its current requirements while rewriting it in Go. Use the MIT license and English by default. Deliver working installation through mise, Homebrew, and go install.

## Authoritative source

The existing implementation is in the dotfiles checkout used to start this task: `.agents/skillctrl/{skillctrl,upstream,lock,ci,update}.py`, its four `*.test.sh` suites, `ci-prompt.md`, and `README.md`. Its gh-aw integration is in `.github/workflows/skillctrl.md`, its compiled workflow and shared engine. Read the implementation and fixtures, not only this overview. Source paths are passed privately to the implementation agent; never commit machine-specific paths.

## Compatibility and safety

- Preserve find, add, update, remove, status, record, --repo and --dry-run; support discoverable help and version output. Emit JSON on stdout and diagnostics on stderr. Exit 0 means success and exit 1 means failure; unresolved CI review is represented in the validated result partition.
- Preserve GitHub owner/repo and HTTPS source validation, explicit skill selection, frontmatter/directory name resolution, relocated skills, source commit and original tree hashes, same-original skip behavior, and compatibility with root project locks (version 1) and legacy version-3 upstream registrations.
- Delegate acquisition to selectable skills and gh command adapters in disposable staging; retain the direct Git adapter for compatibility. Keep skillctrl-specific logic focused on saved intent, validated import, accepted hashes, and optional automation. Command naming must match the upstream CLIs, including install/search/ls/rm aliases. Native backend discovery and release/ref selection may differ. Do not auto-download unpinned tools or silently switch adapters. Clone tracked upstream content without running upstream hooks or skill scripts in the direct Git adapter. Reject symlinks, submodules, Git control files, destination-ignored content, escapes, malformed names, ambiguous matches, and unsupported sources. Prepare all requested results before importing any; remove requires no network. Remove the corresponding intent document when removing a skill; retain unrelated intents.
- Treat `--adapter` as an enum (`skills`, `gh`, `git`) with a default of `skills`, choice completion, and enum help. Reject invalid explicit values during flag parsing and invalid effective `SKILLCTRL_ADAPTER` values before any command runs, including local-only commands and dry runs. An explicit valid flag overrides the environment.
- Keep upstream registration at the repository root in `skills-lock.json`; read existing project locks in place, retain their version and unknown metadata, and migrate `.agents/.skill-lock.json` only after a successful import when no root lock exists. Read-only commands and dry runs must never migrate it. Preserve `.agents/skills`, relative Claude links, and accepted version-2 `.agents/skillctrl/intents/lock.json`. Keep whole-directory Git tree hashing including executable mode; use a private index and never disturb caller staging when recording hashes.
- Separate acquisition from intent operations: add, merge, and update only fetch, validate, import, and register originals, regardless of intent presence. They neither invoke AI nor write the accepted lock. Users edit skill content and saved intent files directly. Do not expose an intent command or start a local AI reviewer. record [names...] explicitly accepts only named verified content without reviewing or changing it; with no names it only prunes ineligible hashes and accepts no content. Deleting intent excludes that skill from acceptance, with stale hashes pruned on the next accepted-lock write. Accepted hashes, status, and automatic CI review include only skills having both upstream registration and saved intent. Handwritten and intent-free skills remain excluded. Advance only explicitly accepted hashes; unresolved content remains unaccepted. Preserve other eligible hashes and prune ineligible legacy entries on the next accepted-lock write. Read registrations and intent eligibility from fixed CI input trees; local selection includes uncommitted registrations without disturbing staging.
- Allow pending local changes while preserving caller staging and unrelated files. Refuse imports that replace skill directories containing pending edits, before importing any skill. Operate in the selected repository in place for both main checkouts and linked worktrees. Do not create worktrees, expose a worktree provider, or depend on Orca. Keep acquisition in disposable staging, atomic preparation, and no implicit commit/push/PR by ordinary installer commands. Remove hardcoded dotfiles ownership/toolchain assumptions so other Git repositories can use the tool.
- Keep external CI reviewer preparation and result validation compatible with the existing workflow. Check reports only local accepted-hash drift offline without importing, reviewing, or accepting content; explicit names scope the report. It requires no acquisition adapter executable and reports differences without failing the command. status reports the same local state for all managed skills, and ci plan selects from fixed commits without network acquisition. Upstream acquisition belongs to explicit update and schedule prepare, so a new upstream version alone never changes local acceptance or CI selection. Local commands require no model or reviewer toolchain. The external CI workflow launches its agent; skillctrl provides trusted preparation and validates target-skill-only changes, secret screening, and unresolved results without launching a reviewer. Do not implement a Go wrapper which merely invokes the old Python code.
- Expose CI-only selection and review instructions as ci plan and ci prompt, with no top-level plan, prompt, or schema command. Preserve trusted checker/input separation, accepted/unresolved partition checks, head-drift rejection, upstream fixed-input verification, scheduled update preparation, final lock status, and safe draft publication behavior. Provide reusable Go commands and documented CI integration. Do not publish a trimmed installer as a full requirements-preserving rewrite.
- Keep code comments, prompts, help, errors, public docs, PR descriptions, review reports and release notes English by default. An accompanying concise Japanese README may be provided, with English comments in its code examples.
- In this development repository, mise must resolve `skillctrl` to a launcher that builds and runs the current checkout, preserving the caller's working directory, arguments, and exit status without replacing the global installation.

## Multiple upstream inputs

- Provide `merge owner/repo:skill... --name NAME` with positional inputs and a required output name. Store the ordered input registrations in a `sources` array on the existing upstream lock entry, with an independent source identity, named skill, source commit, path, and original tree hash for each input. Read existing version-3 single-source records unchanged and preserve unknown record fields. Older binaries do not understand entries with this extension.
- Merge mechanically creates a root routing SKILL.md linking complete original directories in `references/<upstream-skill-name>/`, without intent or AI. Explicit re-merge regenerates routing with the replacement ordered inputs. Update preserves current root output and refreshes every original. Prepare all originals before importing any result. Users customize the root and saved intent directly, then record verified content. CI validation retains the accepted/unresolved partition. Named layout registrations carry sourceLayout: references. Reject case-insensitive source skill-name collisions before acquisition. Preserve unregistered reference files and refuse overlapping reference directories. Keep numeric snapshots for existing registrations during update; explicit merge migrates their registered originals and routing.
- `update` checks all input registrations, including inputs from different repositories and relocated skills. Unchanged originals preserve the merged output. Acquisition never triggers review. Local editing and acceptance are separate. Removing a merged skill removes its registrations, body, and saved intent.
- Keep originals immutable during agent review and bind them to the immutable input trees. Source snapshots must not be independently discoverable as skills. Scheduled input verification checks each original hash and source identity and refuses changes to the merged output before review.
- Preserve local default targeting, pending-edit preservation and in-place repository mutation, JSON output, dry-run behavior, source validation, secret screening, and no implicit commit/push/PR. A dry run reports inputs without network fetches or adaptation. Cover second-input changes, same-original skips, unresolved retries, malformed registrations, partial preparation failure, executable modes, relocation, and rejected source tampering.

- Add and merge share positional owner/repo:skill inputs; --from is rejected. Merge requires --name for its output and does not accept a positional output name. Add imports separate skills from one or more repositories, preparing every input before importing any result; merge combines them. Reject duplicate inputs and case-insensitive skill-name collisions before acquisition, including dry runs. Preserve add source --skill names for acquisition CLI parity; reject mixing --skill with qualified owner/repo:skill inputs or multiple repository sources.
- add --name NAME requires exactly one selected skill (qualified positional input or --skill), changes the destination directory and registration identity, and preserves source file bytes/frontmatter. Record the original upstream skill name independently so update and scheduled validation continue to resolve it; check scopes local acceptance by the destination name. Reject malformed names and multiple selected skills before acquisition.
